ENGENHARIA DE SOFTWARE — 2026.2

SISTEMA DE GERENCIAMENTO DE EVENTOS CIENTÍFICOS USANDO MICROSSERVIÇOS E COMPONENTES DE SOFTWARE

Arthur Carvalho e Ana Leticia Nobre

Repositório GitHub: https://github.com/arthuurca/projeto_Engenharia_de_software Versão de revisão: 31/10/2026

1. APRESENTAÇÃO E ENUNCIADO

Desenvolvemos um sistema web para cadastrar eventos científicos, registrar participantes, controlar inscrições e recomendar eventos por área de interesse. Nosso objetivo foi construir uma versão pequena, com um fluxo completo de uso, demonstrando microsserviços, API Gateway e componentes reutilizáveis.

Os organizadores precisam divulgar os dados dos eventos e acompanhar suas vagas. Os participantes precisam consultar os eventos, realizar inscrições e encontrar atividades relacionadas aos seus interesses. Reunimos essas operações em uma interface simples.

O organizador pode cadastrar eventos e consultar a programação. O participante pode cadastrar seus dados, selecionar seu nome para a demonstração, consultar eventos, inscrever-se e acompanhar suas inscrições e recomendações. Nesta versão acadêmica local, não implementamos autenticação ou controle de permissões. Utilizamos dados fictícios.

O participante possui nome, e-mail e uma área de interesse. O evento possui título, descrição, data e horário de início, local, área e capacidade. Definimos as áreas Computação, Engenharias, Saúde e Ciências Humanas. Não incluímos edição, exclusão, cancelamento de inscrições, pagamentos, certificados, submissão de artigos, envio de e-mails ou aplicativo móvel. As recomendações usam regras simples, sem agentes de IA, que são opcionais no tema.

2. METODOLOGIA E ORGANIZAÇÃO DO TRABALHO

Organizamos o trabalho em três sprints, com um processo ágil simplificado inspirado em Scrum. Usamos o Product Backlog para definir o que construir e os Sprint Backlogs para dividir a execução. O acompanhamento considera os estados A fazer, Em andamento e Concluído. Não adotamos todos os papéis e eventos formais do Scrum; a organização foi adaptada a um trabalho em dupla.

Na divisão inicial, Arthur ficou como responsável previsto pelos microsserviços, pelo Gateway e pelas instruções de execução, e Ana pela interface, pelos componentes e pela organização do relatório. Requisitos, arquitetura, integração, testes e revisão foram definidos como atividades compartilhadas. Essa divisão representa o planejamento; os registros técnicos descrevem os resultados observados sem afirmar reuniões ou retrospectivas que não foram registradas.

Na Sprint 1, foram implementados Gateway, Usuários, Eventos e as telas de cadastro e consulta. Na Sprint 2, foram adicionados Inscrições, Recomendações e o cálculo real de vagas. Nesta revisão da Sprint 3, conferimos os testes, a documentação e os materiais de entrega. O endereço do repositório foi incluído na capa para acompanhar a publicação do código.

RN09Vagas disponíveis correspondem ao limite do evento menos a quantidade de inscrições confirmadas. Uma tentativa recusada não consome vaga.

Datas e horários serão apresentados no fuso de Brasília (America/Sao_Paulo). O sistema deve comparar instantes de maneira consistente; o armazenamento em UTC está definido na arquitetura.

PB01 — Cadastro e seleção do participante

- Com nome, e-mail válido e área permitida, o cadastro é salvo e aparece na lista de participantes. - Ao selecionar um participante, a interface identifica o cadastro usado nas inscrições e recomendações. - Campos vazios, e-mail inválido e área não permitida são recusados com mensagem compreensível. - Um e-mail já cadastrado é recusado, inclusive quando escrito com diferenças de maiúsculas ou espaços nas extremidades. - Sem participantes cadastrados, a interface informa essa situação e permite acessar o cadastro.

PB02 — Cadastro do evento

- Com todos os campos válidos, o evento é salvo e aparece na listagem. - Campos vazios e área não permitida são recusados. - Data passada ou igual ao instante atual é recusada. - Capacidade zero, negativa ou fracionária é recusada.

PB03 — Consulta dos eventos

- Cada evento apresenta título, data e horário, local, área e vagas disponíveis. - Um evento sem inscrições apresenta todas as suas vagas disponíveis. - Após uma inscrição confirmada, a consulta atualizada apresenta uma vaga a menos. - Eventos iniciados ou lotados podem continuar na listagem, mas não permitem nova inscrição. - Sem eventos cadastrados, a interface apresenta uma mensagem de lista vazia.

PB04 — Inscrição

- Com participante e evento existentes, data futura e vaga disponível, a inscrição é confirmada e reserva exatamente uma vaga. - Uma nova inscrição da mesma pessoa no mesmo evento é recusada sem alterar a ocupação. - Evento lotado ou iniciado recusa a inscrição sem criar registro. - Participante ou evento inexistente recusa a operação sem criar registro. - Para um evento com uma vaga restante, duas solicitações simultâneas de participantes diferentes geram apenas uma confirmação. - Sem participante selecionado, a interface orienta a seleção antes de enviar a inscrição.

PB05 — Consulta das inscrições

- A consulta apresenta somente inscrições do participante selecionado, com título, data e local dos respectivos eventos. - Ao trocar o participante selecionado, a listagem corresponde ao novo participante. - Sem inscrições, a interface informa que o participante ainda não está inscrito em eventos.

PB06 — Recomendação

- Para um participante interessado em Computação, um evento futuro dessa área, com vaga e sem inscrição prévia, aparece como sugestão. - Eventos de outra área, iniciados, lotados ou com inscrição do participante não aparecem nas sugestões. - Após uma inscrição, a consulta atualizada de recomendações deixa de sugerir esse evento. - Sem eventos elegíveis, a interface informa que não há recomendações disponíveis. - As sugestões são calculadas por regras simples, sem IA ou serviço externo.

5. ARQUITETURA DO SISTEMA

Navegador (HTML, CSS e JavaScript)
                  |
          API Gateway :3000
          /      |      |       \
 Usuários   Eventos  Inscrições  Recomendações
   :3001     :3002     :3003        :3004
     |         |         |
 usuarios   eventos   inscricoes
 .sqlite    .sqlite    .sqlite

Cada serviço executa em um processo separado. A interface faz as chamadas de negócio somente pelo Gateway. Os serviços consultam as APIs dos demais quando precisam de informações; cada banco é acessado somente pelo serviço proprietário.

Inscrições consulta Usuários e a rota básica de Eventos antes de confirmar. A listagem de Eventos consulta a ocupação em Inscrições. Recomendações consulta interesses, eventos com vagas e IDs das inscrições. As rotas internas de ocupação não fazem novas consultas a Eventos, evitando chamadas circulares.

Os processos escutam localmente em 127.0.0.1, com portas configuráveis. Não utilizamos Docker ou um servidor separado de banco nesta versão.

7. REUSO, ESPECIFICAÇÃO E CÓDIGO DOCUMENTADO

Especificação do código e demonstração

API Gateway

gateway/server.js cria o processo HTTP na porta 3000. Entrega frontend/ por arquivos estáticos e encaminha somente as rotas públicas permitidas para os serviços. Preserva códigos e mensagens das respostas, sem repetir POST. O limite de encaminhamento é 10 segundos; falhas de conexão geram 503 e tempo excedido gera 504. /api/status consulta /health em paralelo e identifica cada serviço como online ou indisponível.

Microsserviços

Serviço / arquivoEntradas e operaçõesPersistência
Usuários — services/usuarios/server.jsPOST /participantes valida nome, e-mail e área; normaliza e-mail. GET /participantes lista; GET /participantes/:id consulta ou retorna 404.usuarios.sqlite: participantes(id, nome, email UNIQUE, area).
Eventos — services/eventos/server.jsPOST /eventos valida dados, início com fuso e capacidade. GET /eventos agrega ocupação para calcular vagas; GET /eventos/:id retorna cadastro básico.eventos.sqlite: eventos(id, titulo, descricao, inicio, local, area, capacidade).
Inscrições — services/inscricoes/server.jsPOST /inscricoes valida referências por HTTP e confirma atomicamente. GET /inscricoes?participanteId lista registros do participante e consulta dados dos eventos. GET /ocupacao e /inscricoes/ids são rotas internas sem encaminhamento no Gateway.inscricoes.sqlite: inscricoes(id, participanteId, eventoId, criadaEm), UNIQUE(participanteId, eventoId).
Recomendações — services/recomendacoes/server.jsGET /recomendacoes?participanteId consulta interesse, eventos e inscrições, aplica filtros e ordena.Sem banco; sugestões calculadas a cada consulta.

Todos usam application e errors de shared/core.js, com JSON de até 32 KB, rota /health e respostas de erro uniformes. Bancos e tabelas são criados automaticamente. SQL usa parâmetros para valores recebidos. Somente o proprietário acessa cada arquivo de banco.

As regras, contratos, códigos HTTP, campos e diagrama estão em Arquitetura (04-arquitetura-e-tecnologias.md). Não existem rotas de edição, exclusão ou cancelamento. A referência a participante não é autenticação: trata-se de uma demonstração local.

Inscrição e recomendação

Na inscrição, as consultas de existência acontecem antes de BEGIN IMMEDIATE. Sem await dentro da transação, a rotina verifica início, duplicidade e contagem, insere e executa COMMIT. Um erro executa ROLLBACK. Essa operação impede ultrapassar a capacidade, e a restrição UNIQUE também protege o par participante/evento. O evento não pode ser editado nesta versão, portanto a capacidade não muda entre validação e confirmação.

A recomendação implementada em services/recomendacoes/server.js usa a regra:

mesma área && início futuro && vagas > 0 && participante ainda não inscrito.

A ordenação é por início e ID. shared/http.js limita consultas internas a três segundos e propaga falhas sem convertê-las em listas vazias. A rota de ocupação não chama Eventos; a consulta básica de evento não chama Inscrições. Assim, a dependência de dados não se transforma em recursão HTTP.

9. TESTES E EXECUÇÃO

Executamos a suíte npm test com 15 testes reportados: um principal e 14 subtestes, todos aprovados. A suíte verifica cadastros, validações, IDs, duplicidade, consultas por participante, vagas, recomendações, eventos iniciados, persistência após reinício e falhas de dependências.

No teste de concorrência, dois participantes solicitaram simultaneamente a última vaga. Apenas uma inscrição recebeu confirmação, e a outra foi recusada por lotação. Nos testes de persistência, encerramos e iniciamos os serviços e conferimos os mesmos registros. Os bancos usados nas verificações são temporários e separados dos dados locais.

Para simular um evento iniciado sem esperar, o teste altera somente o banco temporário de eventos. Não criamos uma rota de edição na aplicação. Ao interromper uma dependência, as operações que precisam dela retornam erro em vez de inventar vagas ou sugestões vazias.

Para executar em outra máquina: 1. Instalar Node.js 24.19.0 ou superior na linha 24, com npm. 2. Extrair o projeto e abrir um terminal na pasta que contém package.json. 3. Executar npm ci para instalar as versões do package-lock.json. 4. Executar npm test para verificar o funcionamento. 5. Executar npm start e abrir http://127.0.0.1:3000. 6. Cadastrar dados fictícios e seguir o roteiro do README. 7. Encerrar os processos com Ctrl+C. Os dados locais ficam preservados em data/.

Uma instalação nova começa sem cadastros. O pacote não inclui node_modules nem os bancos locais; os bancos são criados automaticamente. É necessário acesso à internet para instalar as dependências na primeira vez, mas não para usar o sistema depois.

  const participanteId = id(req.body?.participanteId);
  const eventoId = id(req.body?.eventoId);
  const [, evento] = await Promise.all([
    get('usuarios', `/participantes/${participanteId}`), get('eventos', `/eventos/${eventoId}`)
  ]);
  // All network I/O happens before locking. Capacity is immutable in this version.
  // The count and INSERT are atomic, including requests racing for the last seat.
  db.exec('BEGIN IMMEDIATE');
  let row;
  try {
    if (new Date(evento.inicio).getTime() <= Date.now()) fail(409, 'EVENTO_INICIADO', 'O evento já começou.');
    if (db.prepare('SELECT id FROM inscricoes WHERE participanteId = ? AND eventoId = ?').get(participanteId, eventoId))
      fail(409, 'INSCRICAO_DUPLICADA', 'Você já está inscrito neste evento.');
    const { total } = db.prepare('SELECT COUNT(*) AS total FROM inscricoes WHERE eventoId = ?').get(eventoId);
    if (total >= evento.capacidade) fail(409, 'EVENTO_LOTADO', 'Não há vagas disponíveis neste evento.');

      .run(participanteId, eventoId, new Date().toISOString());
    row = db.prepare('SELECT * FROM inscricoes WHERE id = ?').get(Number(result.lastInsertRowid));
    db.exec('COMMIT');
  } catch (error) { db.exec('ROLLBACK'); throw error; }
  res.status(201).json({ dados: row });

export const ROOT = fileURLToPath(new URL('../', import.meta.url));
export const AREAS = ['Computação', 'Engenharias', 'Saúde', 'Ciências Humanas'];

export function fail(status, codigo, mensagem) {
  const error = new Error(mensagem);
  Object.assign(error, { status, codigo });
  throw error;
}

export function text(value, label, max = 200) {
  if (typeof value !== 'string' || !value.trim() || value.trim().length > max)
    fail(400, 'CAMPO_INVALIDO', `${label}: preencha um texto de até ${max} caracteres.`);
  return value.trim();
}

export function area(value) {
  if (!AREAS.includes(value)) fail(400, 'AREA_INVALIDA', 'Selecione uma área válida.');
  return value;
}

export function id(value) {
  if (!/^[1-9]\d*$/.test(String(value)) || !Number.isSafeInteger(Number(value)))
    fail(400, 'ID_INVALIDO', 'O identificador deve ser um inteiro positivo.');
  return Number(value);
}

export function database(name) {
  const path = resolve(process.env.DATA_DIR || resolve(ROOT, 'data'), `${name}.sqlite`);
  mkdirSync(dirname(path), { recursive: true });
  const db = new DatabaseSync(path, { timeout: 3000 });
  db.exec('PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;');
  return db;
}

export function application(service, db) {
  const app = express();
  app.disable('x-powered-by');
  app.use(express.json({ limit: '32kb' }));
  app.get('/health', (_req, res) => {
    try {
      db?.prepare('SELECT 1').get();
      res.json({ status: 'ok', servico: service });
    } catch {
      res.status(503).json({ erro: { codigo: 'BANCO_INDISPONIVEL', mensagem: 'Banco de dados indisponível.' } });
    }
  });
  return app;
}

export function errors(app) {
  app.use((_req, _res, next) => {
    try { fail(404, 'ROTA_INEXISTENTE', 'Rota não encontrada.'); } catch (error) { next(error); }
  });
  app.use((error, _req, res, _next) => {
    const status = error.status || 500;
    if (status >= 500) console.error(error.message);
    const mensagem = error.type === 'entity.parse.failed' ? 'O corpo deve conter JSON válido.'
      : error.type === 'entity.too.large' ? 'O conteúdo enviado é muito grande.'
      : status < 500 || error.codigo ? error.message : 'Não foi possível concluir a operação.';
    res.status(status).json({ erro: { codigo: error.codigo || (status === 400 ? 'JSON_INVALIDO' : 'ERRO_INTERNO'), mensagem } });
  });
}

/** Each entry point owns its process and closes its database on termination. */
export function listen(app, port, service, db) {
  const server = app.listen(Number(port), '127.0.0.1', () => console.log(`${service}: http://127.0.0.1:${port}`));
  server.on('error', (error) => { console.error(`${service}: ${error.message}`); process.exit(1); });
  const stop = () => {
    server.close(() => { db?.close(); process.exit(0); });
    setTimeout(() => process.exit(1), 2000).unref();
  };
  process.on('SIGTERM', stop);
  process.on('SIGINT', stop);
  return server;
}

/** Reusable labeled control; textContent avoids interpreting user values as HTML. */
export function field({ name, label, type = 'text', options, maxLength, min, step, hint }) {
  const wrapper = document.createElement('div');
  wrapper.className = 'field';
  const caption = document.createElement('label');
  caption.htmlFor = name;
  caption.textContent = label;
  const control = document.createElement(options ? 'select' : type === 'textarea' ? 'textarea' : 'input');
  control.name = name;
  control.id = name;
  control.required = true;
  if (control.tagName === 'INPUT') control.type = type;
  if (maxLength) control.maxLength = maxLength;
  if (min !== undefined) control.min = min;
  if (step !== undefined) control.step = step;
  if (options) {
    const placeholder = new Option('Selecione uma área', '');
    placeholder.disabled = true;
    placeholder.selected = true;
    control.add(placeholder);
    for (const value of options) control.add(new Option(value, value));
  }
  wrapper.append(caption, control);
  if (hint) {
    const help = document.createElement('small');
    help.id = `${name}-help`;
    help.textContent = hint;
    control.setAttribute('aria-describedby', help.id);
    wrapper.append(help);
  }
  return wrapper;
}

async function register(event) {
  const participanteId = Number($('participant-select').value);
  if (!participanteId) return message('registration-message', 'Selecione um participante antes de se inscrever.', 'error');
  if (registrationBusy) return;
  const person = participants.find(row => row.id === participanteId);
  registrationBusy = true;
  renderEvents();
  message('registration-message', 'Confirmando inscrição…');
  try {
    await api('/inscricoes', { method: 'POST', body: { participanteId, eventoId: event.id } });
    message('registration-message', `Inscrição de ${person.nome} em ${event.titulo} confirmada.`, 'success');

  finally {
    await Promise.allSettled([loadEvents(), loadPersonal()]);
    registrationBusy = false;
    renderEvents();
  }
}

async function loadPersonal() {
  const generation = ++personalLoad;
  const person = participants.find(row => String(row.id) === $('participant-select').value);
  registeredIds = new Set(); recommendationRows = [];
  $('registrations-list').replaceChildren(); $('recommendations-list').replaceChildren();
  $('personal-person').textContent = person ? `${person.nome} · ${person.area}` : 'Selecione um participante na área abaixo.';

  message('recommendations-message', person ? 'Carregando recomendações…' : 'Selecione um participante para receber sugestões.');
  renderEvents();
  if (!person) return;
  await Promise.allSettled([
    (async () => {
      try {
        const rows = await api(`/inscricoes?participanteId=${person.id}`);

    })(),

        recommendationRows = rows;

        renderEvents();
      } catch (error) { if (generation === personalLoad) message('recommendations-message', error.message, 'error'); }

function selection() {
  const person = participants.find(p => String(p.id) === $('participant-select').value);
  $('selected-person').textContent = person ? `${person.nome} · ${person.area}` : 'Nenhum participante selecionado.';
  try {
    if (person) localStorage.setItem('participanteId', String(person.id));
    else localStorage.removeItem('participanteId');
  } catch { /* Selection still works when browser storage is disabled. */ }
  message('registration-message', '');
  void loadPersonal();
}

async function loadParticipants(preferred) {
  const generation = ++participantLoad;
  try {
    const rows = await api('/participantes');
    if (generation !== participantLoad) return;
    let previous = preferred || $('participant-select').value;
    try { previous ||= localStorage.getItem('participanteId'); } catch { /* optional persistence */ }
    participants = rows;
    const select = $('participant-select');
    select.replaceChildren(new Option(rows.length ? 'Selecione um participante' : 'Nenhum participante cadastrado', ''));
    for (const person of rows) select.add(new Option(person.nome, String(person.id)));
    select.value = rows.some(p => String(p.id) === String(previous)) ? String(previous) : '';
    select.disabled = !rows.length;
    selection();
  } catch (error) {
    if (generation !== participantLoad) return;
    participants = [];
    $('participant-select').replaceChildren(new Option('Não foi possível carregar', ''));
    $('participant-select').disabled = true;
    $('selected-person').textContent = error.message;
    void loadPersonal();
  }
}

async function loadEvents() {

    eventRows = [];

}

async function loadStatus() {
  const generation = ++statusLoad;
  try {
    const rows = await api('/status');
    if (generation !== statusLoad) return;
    $('services').replaceChildren(...rows.map(service => {
      const item = document.createElement('li');
      const states = { online: 'Online', indisponivel: 'Indisponível', planejado: 'Sprint 2' };
      item.textContent = `${service.nome} · ${states[service.estado]}`;
      item.className = service.estado === 'online' ? 'state-online' : service.estado === 'indisponivel' ? 'state-off' : '';

    }));

    const item = document.createElement('li');
    item.className = 'state-off';
    item.textContent = error.message;
    $('services').replaceChildren(item);
  }
}

function submit(formId, messageId, build, path, after) {
  $(formId).addEventListener('submit', async event => {
    event.preventDefault();
    const form = event.currentTarget;
    const button = form.querySelector('button[type=submit]');
    button.disabled = true;
    message(messageId, 'Salvando…');
    try {
      const body = build(Object.fromEntries(new FormData(form)));
      const saved = await api(path, { method: 'POST', body });
      form.reset();
      message(messageId, 'Cadastro realizado com sucesso.', 'success');
      await after(saved);
    } catch (error) { message(messageId, error.message, 'error'); }
    finally { button.disabled = false; }
  });
}

import { spawn } from 'node:child_process';
import { ROOT } from '../shared/core.js';

// Separate OS processes keep the services independently executable.
const files = ['services/usuarios/server.js', 'services/eventos/server.js', 'services/inscricoes/server.js', 'services/recomendacoes/server.js', 'gateway/server.js'];
const children = [];
let stopping = false;
function stop(code = 0) {
  if (stopping) return;
  stopping = true;
  for (const child of children) if (child.exitCode === null) child.kill();
  process.exitCode = code;
}
for (const file of files) {
  const child = spawn(process.execPath, [file], { cwd: ROOT, stdio: 'inherit', windowsHide: true });
  children.push(child);
  child.on('error', error => { console.error(error.message); stop(1); });
  child.on('exit', code => { if (!stopping) { console.error(`${file} encerrou (${code}).`); stop(code || 1); } });
}
process.on('SIGINT', () => stop());
process.on('SIGTERM', () => stop());
